# DockerBox 前端测试清单

> 用途：每次代码变更后，用此清单快速验证所有页面和功能是否正常。
> 更新：发现新问题或新增功能时，及时补充对应测试点。
> 验证方式：Playwright 自动化 + 后端 API 对比真实系统数据。

---

- [ ] 启动前端 dev server（`cd frontend && bun run dev`）或部署到测试环境

- [ ] 准备测试账号（默认 `admin` / `admin123`）

## 3. 概览页 `/overview`

### 3.1 系统信息 — 数据准确性验证

> **验证方法**：Playwright 读取页面显示值 → SSH 执行系统命令获取真实值 → 对比。

| 指标 | 页面显示 | 系统真实值来源 | 允许误差 |
|------|----------|----------------|----------|
| CPU% | 页面数值 | `top -bn1 \| grep "Cpu(s)"` 或 `mpstat 1 1` | ±5%（动态波动） |
| CPU 核心数 | 页面数值 | `nproc` | 精确匹配 |
| 内存已用/总量 | 页面数值 | `free -b \| grep Mem` 第2、3列 | 精确匹配 |
| 内存使用率 | 页面百分比 | `free \| grep Mem` 计算 (used/total*100) | ±2% |
| 网络下行 | 页面数值 | `cat /proc/net/dev` 计算差值 | 趋势一致即可 |
| 网络上行 | 页面数值 | `cat /proc/net/dev` 计算差值 | 趋势一致即可 |
| 负载 1m/5m/15m | 页面数值 | `cat /proc/loadavg` | 精确匹配 |

- [ ] CPU% 在合理范围内（0-100%，与 `top` 输出差异 < 5%）
- [ ] CPU 核心数与 `nproc` 一致
- [ ] 内存已用量与 `free` 输出一致
- [ ] 内存总量与 `free` 输出一致
- [ ] 负载值与 `cat /proc/loadavg` 一致
- [ ] 网络流量数据在增长（刷新前后对比）

### 3.2 Docker 统计 — 数据准确性验证

> **验证方法**：Playwright 读取页面数值 → SSH 执行 `docker` 命令对比。

| 指标 | 页面显示 | 系统真实值来源 |
|------|----------|----------------|
| 运行中容器数 | 页面数值 | `docker ps -q \| wc -l` |
| 总容器数 | 页面数值 | `docker ps -aq \| wc -l` |
| 已停止容器数 | 页面数值 | `docker ps -aq --filter status=exited \| wc -l` |
| Compose 项目数 | 页面数值 | `docker compose ls -q \| wc -l` |
| 镜像数量 | 页面数值 | `docker images -q \| wc -l` |
| 镜像总大小 | 页面数值 | `docker system df \| grep Images` |

- [ ] 运行中容器数 = `docker ps -q | wc -l`
- [ ] 总容器数 = `docker ps -aq | wc -l`（运行中 + 已停止）
- [ ] 已停止容器数 = `docker ps -aq --filter status=exited | wc -l`
- [ ] Compose 项目数 = `docker compose ls -q | wc -l`
- [ ] 镜像数量 = `docker images -q | wc -l`
- [ ] 镜像总大小与 `docker system df` 一致

### 3.3 图表
- [ ] CPU 折线图有数据点，非空
- [ ] 内存折线图有数据点，非空
- [ ] 网络折线图有数据点，非空
- [ ] 窗口缩放后图表自适应（不溢出、不截断）

## 4. 容器页 `/containers`

### 4.1 容器列表 — 数据准确性验证

> **验证方法**：Playwright 读取表格 → SSH 执行 `docker inspect` 对比。

- [ ] 容器总数与概览页一致，与 `docker ps -aq | wc -l` 一致
- [ ] 每个容器的运行状态（运行中/已停止）与 `docker inspect --format '{{.State.Status}}'` 一致
- [ ] 每个容器的端口映射与 `docker inspect --format '{{json .NetworkSettings.Ports}}'` 一致
- [ ] 每个容器的运行时间与 `docker inspect --format '{{.State.StartedAt}}'` 计算一致
- [ ] 容器 CPU% 在合理范围（0-100%）
- [ ] 容器内存值与 `docker stats --no-stream` 交叉验证（误差 < 10%）

### 4.2 搜索过滤
- [ ] 搜索框输入关键词，列表只显示匹配的容器
- [ ] 清空搜索框，列表恢复全部容器
- [ ] 无匹配时显示空状态

### 4.3 容器操作 — 结果准确性验证

| 操作 | 验证方式 |
|------|----------|
| 停止容器 | 操作后 SSH 执行 `docker inspect --format '{{.State.Status}}' <name>` 确认为 `exited` |
| 重启容器 | 操作后 SSH 执行 `docker inspect --format '{{.State.Status}}' <name>` 确认为 `running` |
| 查看日志 | 弹窗内容与 `docker logs <name>` 输出一致 |
| 查看 Inspect | 弹窗 JSON 与 `docker inspect <name>` 输出一致 |

- [ ] 停止容器后，列表状态更新为"已停止"
- [ ] 停止容器后，SSH 验证 `docker inspect` 状态确实为 `exited`
- [ ] 重启容器后，列表状态更新为"运行中"
- [ ] 重启容器后，SSH 验证容器状态确实为 `running`
- [ ] 日志弹窗内容与 `docker logs` 一致
- [ ] 关闭日志弹窗后，SSE 连接断开（Network 面板无残留连接）
- [ ] 终端弹窗可执行命令并返回结果
- [ ] Inspect 弹窗 JSON 数据与 `docker inspect` 一致
- [ ] 端口链接可点击，跳转到正确的地址

### 4.4 容器详情 `/containers/[id]`
- [ ] 容器名称、镜像、状态与 `docker inspect` 一致
- [ ] 端口映射与 `docker inspect` 一致
- [ ] 操作按钮正常工作（启动/停止/重启/删除）

### 4.5 容器终端 `/containers/[id]/terminal`
- [ ] WebSocket 连接成功（Network 面板确认）
- [ ] 输入 `echo hello` 返回 `hello`
- [ ] 输入 `ls /` 返回文件列表

### 4.6 清理功能
- [ ] 点击"清理未使用的镜像和网络"
- [ ] 清理后，`docker images -q | wc -l` 减少
- [ ] Toast 显示清理结果（删除数量、释放空间）
